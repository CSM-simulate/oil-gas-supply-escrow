# Мини аудит смарт контракта поставки

Объект: `contracts/OilGasEscrow.sol`. Дата: 11 октября 2026 года. Проверка выполнена GPT, компилятором Solidity 0.8.28, тестами Hardhat и Slither 0.11.3. Итог: 84 теста проходят; Slither не выявил High/Medium. Ниже отдельно указаны обнаруженная ошибка, проверенные меры защиты, замечания анализатора и ограничения модели.

## Ошибка сгенерированного черновика

**A01 Поздняя доставка блокировала возврат по сроку — исправлено.**

Первый вариант `markDelivered` проверял только роль поставщика и статус Funded. Поставщик мог вызвать функцию уже после дедлайна до транзакции покупателя на возврат. Статус становился Delivered, после чего `refund` отклонялся. По последствиям для средств эта ошибка оценена в рамках мини-аудита как высокая серьёзность; это оценка GPT, не результат детектора Slither.

Два реальных теста с timestamp ровно deadline и deadline + 1 ожидали `DeadlinePassed`, но транзакция не откатывалась. Вывод: `0 passing, 2 failing`; сохранён `run-artifacts/draft-regression.log`.

Исправление:

```solidity
_expectStatus(batch, Status.Funded);
if (block.timestamp >= batch.deadline) revert DeadlinePassed(id);
batch.status = Status.Delivered;
```

При timestamp >= deadline поставщик больше не может изменить Funded; покупатель сохраняет возврат. Проверки на deadline −1/0/+1 проходят.

## Меры защиты и результаты проверки

| Риск | Реализация | Проверка |
|---|---|---|
| Поставщик разрешает себе оплату | releasePayment только buyer | Попытки supplier и outsider отклоняются |
| Повторная выплата или возврат | Проверка статуса, терминальные Released/Refunded | Проверены все 20 недопустимых переходов |
| Повторный вход при ETH-переводе | nonReentrant на четырёх денежных функциях, CEI | Повторный вход на ту же/другую партию и в fundBatch заблокирован |
| Потеря статуса при отказе получателя | Проверка success; полный откат транзакции | Выплата, refund и reject сохраняют состояние и допускают повторную попытку |
| Подмена условий партии | Нет функции изменения данных, повтор ID запрещён | Проверяется неизменность всех метаданных |
| Неточная оплата | msg.value == priceWei | Ноль, недоплата и переплата отклоняются |
| Использование чужой оплаты | Учёт по партии и totalEscrowed | Разные цены, смешанные исходы, последовательность 32 партий |
| Неизвестный ID похож на Created | Отдельный _exists, BatchNotFound | ID 0 допустим, отсутствующий ID отклоняется |
| Изменение ролей или отказ от роли | Нет администратора, renounceRole запрещён | Grant/revoke/renounce отклоняются |
| Неверное равенство общего баланса | Инвариант balance >= totalEscrowed | Принудительные 7 wei остаются сверх обязательств |

Эти риски анализировались при генерации и проверке. Таблица не означает, что каждый из них присутствовал как ошибка в черновике. Реально воспроизведённый дефект указан в A01.

## Замечания Slither

Анализ проведён после чистой компиляции финальной версии. Зависимости OpenZeppelin и вспомогательные тестовые контракты исключены из выдачи замечаний; анализируется основной контракт. Полный JSON с `success: true` и текстовый вывод приложены в `run-artifacts/`.

В JSON-отчёте локальные абсолютные пути заменены нейтральным префиксом `/project/`. Замечания, уровни серьёзности, номера строк и остальные результаты анализа сохранены.

| Детектор | Число | Уровень | Решение |
|---|---|---|---|
| timestamp | 4 | Low, confidence Medium | Принято как свойство логики срока |
| low-level-calls | 1 | Informational, confidence High | Проверен success, применены CEI и ReentrancyGuard |

**Timestamp.** Сравнения времени присутствуют в createBatch, fundBatch, markDelivered и refund. Дедлайн по заданию зависит от времени блока; это не источник случайности. Влияние производителей блоков на точное время остаётся ограничением, поэтому стороны должны использовать реалистичные сроки, а не секундные бизнес-интервалы. Точная программная граница проверена тестами.

**Низкоуровневый call.** Перевод ETH выполняется с проверкой результата. До вызова изменены статус и обязательства; повторный вход в денежные функции запрещён. Ошибка перевода откатывает изменения. Использование call сохранено для получателей-контрактов, которым может не хватить фиксированного лимита газа `transfer`.

Команда проверки использует `--fail-medium` и завершилась с кодом 0. Без этого параметра Slither по умолчанию может вернуть ненулевой код и для этих Low/Informational-замечаний. Пять замечаний не скрывались и не представлены как «нулевой результат аудита».

Компилятор также предупреждает о `selfdestruct` в `contracts/test/ForceEther.sol`: он используется только для adversarial-теста принудительного ETH, выполняется в конструкторе и не входит в основной контракт или скрипт его развёртывания.

## Оставшиеся ограничения

1. **Подтверждение реальной поставки вне блокчейна.** Поставщик заявляет доставку, покупатель оценивает объём и качество. Хэши не доказывают физические события.
2. **Нет независимого разрешения споров.** Покупатель может отклонить реальную поставку либо удерживать Delivered без решения. Арбитр и дополнительный срок приёмки требуют расширения согласованных условий.
3. **Фиксированные участники.** Потеря ключа не восстанавливается контрактом; постоянно отклоняющий ETH адрес может заблокировать завершение. Retry помогает только если получатель способен изменить своё поведение.
4. **Принудительно поступившие средства.** Их нельзя распределить как оплату партии; функции изъятия избытка нет. Это сохраняет отсутствие административного доступа к эскроу.
5. **Проверка не является формальным доказательством.** Последовательность 32 партий воспроизводима, но не исчерпывает все возможные исполнения. Внешний независимый аудит в рамках задания не выполнялся.

Ограничения отражены в спецификации и README. Основные денежные сценарии и заявленные инварианты проверены фактическими запусками.
